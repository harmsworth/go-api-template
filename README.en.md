# go-api-template

**English** | [简体中文](README.md)

A **learning-oriented Go Web API template**. It is not an enterprise-grade scaffold — it is deliberately kept small,
meant to be copied and adapted, and shipped with a step-by-step manual rebuild tutorial ([docs/init/](docs/init/00-overview.md)).

> Recommended way to learn: read this README → follow docs/init/ in order and rebuild the whole project by hand in an empty
> directory → come back and compare the differences, then think about the trade-offs → finally use this template for your own small project.

## Tech stack

| Component | Purpose |
| --- | --- |
| Go 1.26.x | Language and toolchain |
| Gin | HTTP framework (runtime only, routes registered manually) |
| GORM | MySQL ORM |
| golang-migrate | Database schema migrations (the only migration path; no AutoMigrate) |
| Protobuf + Buf | API contract management and code generation |
| Protovalidate | Request validation (rules live in the proto files) |
| JWT (golang-jwt/v5) | Login state, HS256 access token |
| automaxprocs | Automatically corrects GOMAXPROCS inside containers |

**Deliberately left out**: Wire, gRPC, grpc-gateway, Redis, Kafka, OpenTelemetry, automatic mock tooling.
They are not needed yet — add them when a requirement shows up (see [docs/next-step.md](docs/next-step.md)).

## How to run

Prerequisites: Go 1.26+, Docker (or a local MySQL),
[migrate CLI](docs/init/05-migrate.md), [protoc-gen-go](docs/init/06-protobuf-buf.md) (only needed when changing proto files).

```bash
# 1. Start MySQL (local dev database todo_x)
docker compose up -d

# 2. Run database migrations (no auto-create; create todo_x first, see docs/init/04-mysql.md)
make migrate-up

# 3. Start the service
make run

# 4. Try it
curl http://localhost:8080/healthz
```

The full curl flow for register / login / accessing protected endpoints is in [docs/init/14-run-and-check.md](docs/init/14-run-and-check.md).

## Directory layout

```text
go-api-template/
├── cmd/server/            # main.go: every dependency is wired by hand here (no Wire)
├── configs/               # config.yaml: local configuration
├── docs/
│   ├── init/              # ★ step-by-step tutorial to rebuild this project from scratch (the core artifact)
│   ├── architecture.md    # architecture notes and design trade-offs
│   └── next-step.md       # upgrade roadmap (add on demand, never in advance)
├── gen/go/                # Go code generated by buf (intentionally committed)
├── internal/
│   ├── app/               # route registration + HTTP server
│   ├── platform/          # shared capabilities: config / database / jwt
│   └── user/              # User feature (package by feature)
├── migrations/            # SQL migration files (golang-migrate)
├── proto/                 # API contract (proto-first)
├── buf.yaml / buf.gen.yaml
├── docker-compose.yml     # MySQL only
└── Makefile
```

## Common commands

| Command | What it does |
| --- | --- |
| `make run` | Start locally with `go run ./cmd/server` |
| `make build` | Build to `bin/server.exe` |
| `make test` | `go test ./...` (integration tests need `MYSQL_TEST_DSN`, otherwise they are skipped) |
| `make lint` | `go vet ./...` |
| `make buf-lint` / `make buf-generate` | Lint protos / generate code |
| `make migrate-up` / `make migrate-down` | Apply / roll back one migration |

If you don't have `make`, just copy the raw command from the corresponding Makefile target.
